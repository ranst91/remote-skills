---
title: TypeScript client
description: Discover and activate Remote Skills from Node.js server runtimes.
---

`@remote-skills/client` is a server-runtime package. It intentionally rejects browser imports because local cache, archive, and network-policy guarantees rely on server facilities.

Install the locally built and approved tarball; v0 documentation does not imply registry availability.

```bash
pnpm add ./artifacts/remote-skills-client-0.0.1.tgz
```

## Origin-bound session

```ts
import { createRemoteSkills } from "@remote-skills/client";

const client = createRemoteSkills({
  origins: {
    acme: {
      url: "https://skills.example.com",
      timeoutMs: 30_000,
      retries: 2,
    },
  },
});

const session = await client.session("acme");
try {
  const entries = await session.catalog(); // metadata only
  const skill = await session.activate("code-review", "1.4.x");

  console.log(skill.version, skill.digest);
  console.log(skill.instructions);
  const resources = await skill.list("references/");
  const security = await skill.read("references/security.md");
  const template = await skill.readBytes("assets/template.bin");
} finally {
  await session.close();
}
```

`activate()` downloads and verifies the complete artifact if the object cache does not already contain it. `read()` uses strict UTF-8; `readBytes()` is explicit binary access; `list()` returns normalized path, size, and media-type metadata without bodies. These resource calls are context-lazy and make no further network request.

## Aggregate catalogs and refresh

```ts
const aggregate = await client.catalog({ strict: false });
for (const entry of aggregate.entries) console.log(entry.originAlias, entry.name);
for (const failure of aggregate.failures) console.error(failure.originAlias, failure.error.code);

await client.refresh("acme"); // future sessions only
```

Non-strict aggregation returns healthy entries plus explicit per-origin failures. Strict aggregation throws if any origin fails. Aliases are explicit identities; identical skill names at two origins never receive silent precedence.

Sessions also implement async disposal (`await using`). Closing releases local pins; it does not delete verified cache content. See [cache and offline behavior](/docs/cache-and-offline).
