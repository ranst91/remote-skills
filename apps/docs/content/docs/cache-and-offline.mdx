## Cache is local storage

The production default is a bounded disk cache under the operating system cache directory. Objects are keyed by verified SHA-256 digest, so two entries with identical bytes share one object. Catalog state is separate and keyed by canonical well-known URL plus confirmed non-secret scope when persistence is allowed.

The cache is disposable and rebuildable; it is not an installation. Memory-only and custom cache backends are available when their lifecycle better fits the host.

## Full download, context-lazy reads

Activation downloads the **complete artifact**, verifies it, and extracts an accepted archive locally before returning. It therefore consumes network bandwidth and disk even if the agent later reads only one reference. Context is **context-lazy**: instructions are exposed first, and `read()` loads selected local resources into application/model memory with no additional network request.

For containers, a persistent volume can reuse immutable objects across restarts. An ephemeral cache repeats network, hashing, extraction, and storage after restart. Account for that cost or choose image-local skills when independent remote distribution is unnecessary.

## Freshness and updates

Catalogs honor `ETag`, `Last-Modified`, `Cache-Control`, and `304 Not Modified`. A session consults its catalog once. `client.refresh(alias?)` forces conditional revalidation for **future sessions** only; it never mutates a live session or its digest pins. There is no polling.

If an online refreshed catalog removes a skill or release, a new session cannot resurrect it from cached object bytes. The provider's current authorized catalog is authoritative. Existing sessions retain already pinned bytes.

## Offline policy

- An existing session continues reading its verified pinned object offline.
- A new session fails closed by default if it cannot validate its catalog.
- Explicit stale mode may use a verified older catalog only within a configured maximum age and surfaces `stale` metadata.

Stale mode weakens the immediacy of publisher removal, so keep it opt-in and bounded. Corrupt objects are rejected, not treated as cache misses that silently change security semantics.

## Eviction and concurrency

Least-recently-used eviction respects configured age/size bounds and skips live session leases. Private temporary writers, exact digest verification, no-clobber publication, process registrations, and a shared digest mutation gate let TypeScript and Python processes use one `cache-v1` directory without exposing partial objects. Crashed temporary and coordination records are reclaimed only after bounded age and liveness checks.
