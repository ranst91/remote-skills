---
title: Publisher configuration
description: The strict declarative remote-skills.json schema and its defaults.
---

`remote-skills.json` is optional, declarative JSON. Loading it never executes repository code. Unknown keys fail validation so a typo cannot silently change a build.

```json title="remote-skills.json"
{
  "$schema": "https://remote-skills.dev/schemas/config/0.0.1.json",
  "sourceRoots": ["skills"],
  "outDir": "dist",
  "format": "tar.gz",
  "strict": false,
  "limits": {
    "catalogBytes": 1048576,
    "archiveBytes": 52428800,
    "extractedBytes": 104857600,
    "files": 1000,
    "fileBytes": 10485760
  },
  "dev": {
    "host": "127.0.0.1",
    "port": 8787
  }
}
```

All fields are optional and receive the displayed defaults.

## Fields

- `$schema` identifies the versioned publisher configuration schema.
- `sourceRoots` lists project-relative directories whose immediate children are skill candidates.
- `outDir` is the project-relative completed deployment tree and must not overlap a source root.
- `format` is `tar.gz` or `zip`; single-file skills remain `skill-md` unless `--archive` is supplied.
- `strict` promotes validation warnings to errors.
- `limits` bounds catalog bytes, compressed artifacts, extracted bytes, file count, and per-file bytes.
- `dev.host` and `dev.port` control the local development server. A non-loopback host additionally requires the CLI's `--unsafe-host` acknowledgement.

CLI flags override effective configuration without rewriting the file. `--out-dir` and `--prior-output` remain inside the project. Source and output paths cannot escape or overlap.

Credentials never belong in `remote-skills.json`. Supply verify-only headers using `--header-env`, and configure consumer credentials in the host application's secret-management layer.

The checked-in schema is also served from `/schemas/config/0.0.1.json` by this documentation application.
